# Debug report — theme-init.js 404 on GitHub Pages

**Date:** 2026-03-20 09:30
**Class:** runtime
**Status:** Fixed

## Bug

When the app is served from GitHub Pages, the browser requests `theme-init.js` at the root path and gets a 404, because the `<Script>` src ignores the configured `basePath`.

## Reproduction steps

1. Deploy to GitHub Pages at `https://jblanper.github.io/clarity/`
2. Open the page in a browser with DevTools → Console open
3. Observed: `theme-init.js:1 Failed to load resource: the server responded with a status of 404 (Not Found)` — request goes to `https://jblanper.github.io/theme-init.js`
4. Expected: script loads from `https://jblanper.github.io/clarity/theme-init.js`

## Root cause

`app/layout.tsx:35` used `<Script src="/theme-init.js" strategy="beforeInteractive" />`.
Next.js does **not** automatically prepend `basePath` to `next/script` sources when
`strategy="beforeInteractive"`. With `basePath: "/clarity"` set in `next.config.ts`, the
static export placed `theme-init.js` at `/clarity/theme-init.js`, but the browser requested
`/theme-init.js` — the bare absolute path.

Offending code:
```tsx
<Script src="/theme-init.js" strategy="beforeInteractive" />
```

## What was tried

N/A — root cause identified immediately from the 404 URL in the console error.

## Fix

`app/layout.tsx:35` — changed `src` to include the basePath explicitly:

```tsx
<Script src="/clarity/theme-init.js" strategy="beforeInteractive" />
```

## Scope check

Searched all `app/` files for absolute `src="/"` patterns. No other instances found —
this was the only `<Script>` tag using an absolute path. All `<Image>` and `<Link>`
components in the codebase use relative or Next.js-managed paths that respect basePath
automatically.

## CLAUDE.md update

Not needed — the fix is a single known quirk of `strategy="beforeInteractive"`. If a
second `beforeInteractive` script is ever added, the same rule applies: hardcode
`/clarity/` prefix.
